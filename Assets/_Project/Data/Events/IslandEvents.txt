#  press play; nothing has to be rebuilt and no C# has to be touched.
#
#  THE ONE RULE: every line fires and the director moves straight to the next.
#  The only line that ever blocks is `wait`. Scan the left column for it and you
#  know exactly where the level pauses.
#

[main]

# A beat before the first message, so it does not land in the middle of the
# scene-load hitch.
wait  seconds=1

# Sets the objective but does NOT announce it (announce=false, Carlos 2026-09-10 —
# drop the "Homework: Kill N old timers" popup from the demo). text= is kept
# non-empty anyway: Objective.Text still feeds the pause menu once MRM-19 lands,
# so it needs to stay in sync with kills= even though nothing shows it today.
# 100 is the real demo target (raised from 50, Carlos, 2026-09-10). This is no
# longer a fixed pool to drain — DemoSpotterPopulationManager continuously
# replenishes Spotters toward a floor (plus flare/panic reinforcement waves), so
# 100 is reachable over a long enough session regardless of how many are alive
# at once. Simultaneous alive Spotters are separately hard-capped at
# MoonlightTunables.SpotterPopulationMax (25) so the population/wave systems
# don't stack into an unbounded pile. If you change kills=, change the wording
# in the same line — nothing keeps them in sync for you.
objective  kill_spotters  text="Kill 100 old timers"  kills=100  kind=Spotter  announce=false

# Waits forever on purpose. This is a player-progress wait: it resolves when the
# twenty are dead and never otherwise, and timing it out would hand out a win
# nobody earned. See WaitVerb's class doc for the full timeout policy.
wait  objective=kill_spotters

win  "Good boy"
