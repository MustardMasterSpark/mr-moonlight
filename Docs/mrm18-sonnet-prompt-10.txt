TRAPS ALREADY FOUND, DON'T REDISCOVER
- GutenbergTextura/GabrieleBandAah/Kurland/NotoSerif SDF font assets have a known dead-atlas
  failure mode (see Docs/debug-tools.md's Font section) - GabrieleBandAah SDF v3 is the
  already-fixed version; don't touch it or recreate it without reading that section first.
- SpecialElite SDF.asset (the debug-overlay font) WILL show as modified in git status after any
  session that renders new debug-overlay text in Play Mode - it's a Dynamic-atlas TMP font that
  bakes newly-seen glyphs into its own asset at runtime, harmless, safe to always exclude from
  commits. Confirmed this session via an isolated bare Play->Stop test (no other code running).
  Don't waste time re-investigating it as a bug.
- VP_HazeGlobalFog.asset / CRTSettings.active flipping is NOT a recurring issue (was investigated
  and ruled out this session, confirmed via a clean isolated bare Play->Stop cycle) - if it's ever
  seen modified again, that's a NEW occurrence worth investigating fresh, not the same non-issue.
  It also has zero visual effect on this scene regardless (Main Menu's own CRT volume uses
  VP_MainMenuCRT.asset, a different profile).
- CanvasGroup.DOFade / AudioSource.DOFade don't resolve in this project - use
  DOTween.To(() => x, v => x = v, target, duration) directly, or SetEase(AnimationCurve) the way
  GroupFadeReveal does for a tunable ease.
- Editor screenshots/UnityStats lie when the Editor window isn't focused - verify behavioral fixes
  via direct state reads in Play Mode (execute_code) or a real build, not by trusting a screenshot
  alone. Same applies to background AssetDatabase work stalling unfocused (kickstart.md §B.3a).
