TRAPS FOUND THIS SESSION, DON'T REDISCOVER (full detail in the two docs named above)
1. A shader loop bounded by a MATERIAL UNIFORM (not a compile-time constant) silently compiles to
   Unity's magenta error shader with ZERO Console output - no error, no warning. If you ever see an
   unexplained solid-magenta UI element with a clean Console, check for this first. Fix: loop
   bounds must be #define compile-time constants.
2. _MainTex_TexelSize is NEVER populated for a uGUI Image - CanvasRenderer binds sprite textures
   directly at draw time, bypassing Material.SetTexture (which is what normally auto-populates that
   companion property). Reads back as the (1,1,1,1) default with no error. Any custom UI shader
   that needs to know the sprite's real pixel size must get it from script
   (image.sprite.texture.width/height) and push it in as a custom uniform.
3. UnityEngine.UI.Graphic.color (Image.color) is packed into the mesh as a byte-precision vertex
   color - any channel above 1.0 silently clamps to 1.0 with NO visual difference from exactly 1.0.
   A ">1 multiply to brighten" trick works fine on a real Renderer/Material but can NEVER brighten
   a uGUI Image via Graphic.color, structurally, on any button in this project. If a "brighter/
   whiter" ask ever comes up again for UI, reach for a shader that lerps toward white in the
   fragment stage instead - never Image.color above 1.
4. The main menu has a pre-existing idle/ambient auto-fade (buttons + title fade out after a
   stretch of real-time inactivity, unrelated to anything built this session) - if you're testing
   live and the buttons vanish mid-session, that's this, not a regression. Force
   ButtonGroup's CanvasGroup.alpha = 1 to keep testing.
5. Editor screenshots/game-view captures can be unreliable when the Editor window isn't focused
   (kickstart.md §B.3a, confirmed again this session) - verify behavioral fixes via direct
   component/material state reads in Play Mode (execute_code) alongside screenshots, not
   screenshots alone.
