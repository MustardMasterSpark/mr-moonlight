**⚠️ THE ONE THING TO CARRY INTO THIS SESSION: CHECK THE VENDOR FIRST.** The 2026-09-16 FPS
investigation burned an entire session chasing "what is our code doing wrong" — QualitySettings,
Application.targetFrameRate, driver settings, DXGI presentation modes, three-monitor refresh rates
— before finding the real answer was a PolymindGames vendor asset
(`GraphicsOptions.cs`, `[RuntimeInitializeOnLoadMethod]` + `Apply()`) silently force-setting
`QualitySettings.vSyncCount = 1` on every boot, invisible because its UI (`GraphicsOptionsUI.cs`)
had already been deleted as "dead" without realizing the underlying data asset was still live.
**For this housekeeping session specifically:** item 2 below ("Code cleanup") should explicitly
include auditing `Assets/_Project/Code/Vendor/*` for the same pattern — anything with
`RuntimeInitializeOnLoadMethod`, a `Manager<T>` singleton, or a `UserOptions<T>.Instance` access
that silently applies its own values with no UI or Linear issue tracking it. Don't re-derive this
from scratch; the grep pattern that found it is in the mrm18 doc section referenced above.

**Audio-specific thread to check, since this session is audio-scoped:** `AudioManager.cs`
(vendor, `Assets/_Project/Code/Vendor/PolymindGames/Runtime/Audio/AudioManager.cs`) writes to a
serialized `AudioMixer` field using exposed-parameter names `"MasterVolume"`, `"EffectsVolume"`,
`"AmbienceVolume"`, `"MusicVolume"`, `"UIVolume"`, driven by a completely separate
`AudioOptions.Instance` settings source — not `GameSettings`/`SettingsPanel`'s sliders.
`"MasterVolume"` is the exact same exposed-param string our own sliders write to on
`MoonlightMixer.mixer`. **Not confirmed as a live conflict** — nobody checked yet whether
`AudioManager` is actually instantiated in `MainMenu.unity`/`Island.unity`, or whether its
`_audioMixer` field even points at `MoonlightMixer.mixer` vs. some other vendor-only mixer asset.
Same bug shape as the vSync one — worth checking early in this session before doing any other
audio work, since if it IS live, any audio tuning done without knowing about it could get
silently overwritten.
