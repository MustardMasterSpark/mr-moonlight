=== OPTIONS TO TEST (my order, cheapest/most promising first) ===
1. Shadows (prime suspect for the slow distant view, hypothesis H16 in performance-sessions section 3):
   BRGPrototypeExtraData per prototype: forceDisableShadows (small shrubs/dead trees), maxShadowCascade (e.g. 1-2 so
   far trees cast no shadow), minShadowLOD (shadows from a lower LOD). Also URP shadow distance / cascade count.
   Config shadowCasterOcclusion is already on.
2. Distance density thinning (BRGPrototypeExtraData.enableDistanceDensity, densityStartDistance / EndDistance /
   MinFraction / FadeWidth): thin far trees and far foliage instead of drawing them all. Likely the biggest win
   for the distance view; check the fade looks fine in fog.
3. Per-prototype minScreenSize (BRGPrototypeExtraData) and config defaultSmallMeshSize for foliage, with
   defaultSmallMeshFadeMode crossfade so small things fade instead of pop.
4. Mesh LOD screen sizes on BRGMeshLodData (more aggressive than 1/.5/.25/.1), crossfade mode. Build 59 showed
   triangles are NOT the limit, so expect little; do it last or skip.
5. Occlusion: scene 09 has NO Umbra bake (its occlusion reference was cleared when it was copied from 07, see
   Docs/scene-numbering.md), so builds 57-60 ran on BRG's GPU (HZB) occlusion alone and still beat Flora + the
   baked Umbra of scene 07. Test: bake Umbra for scene 09 (useBakedOcclusionCulling is on, so BRG would use it),
   then A/B useGPUOcclusionCulling on/off, hzbTightness, useHZBRetestPass. Bake = ~57 MB data, Git LFS rule exists.
6. Terrain streaming: allowAsyncDetailLoading, terrainMaxUploadsPerFrame, detail chunk size (32 m), and whether
   the pre-extracted terrain data asset (autoBake on build) is actually produced and used in builds.
7. `useUnityTransforms` cost: it is the vendor's slower, allocating path. Alternative that keeps BRG's fast path:
   fix the 48 child-renderer detail prefabs (renderer on the root) and switch layers off by painting/biomes
   instead. Check GC/hitches in the 1% low first; only change if it shows.
8. Things that do not help perf but matter: enablePerInstanceColor (colour variation for free?), SpeedTree wind
   (enableSpeedTreeWind; our trees use Retro Lit wind, verify wind still animates under BRG).
9. Foliage design (Carlos, later): bring back chosen flowers from the 48 hidden layers per biome
   (Desktop/Foliage_Distribution_Sheet.xlsx holds the per-biome rules). Not this session unless he asks.

=== TRAPS ALREADY FOUND (do not rediscover) ===
1. BRG draws terrain-detail prefabs whose renderer is on a CHILD object; Unity's detail system (and Flora) rejects
   them silently ("Renderer component is missing"). 48 of the 90 island layers are like that (asters, violets,
   daisies, poppies, mushrooms, Fern_01A-03A, Old_RF bushes/ferns). With BRG's default path the island had 4.94 M
   detail instances instead of 1.93 M and ran 135-139 fps. useUnityTransforms ON = Flora's set.
2. BRG ignores native Mesh LOD unless the object has a BRGMeshLodData component (no error, just full detail).
3. Builds need BRGIRConfig.asset in Preloaded Assets and BatchRendererGroup Variants = Keep All (m_BrgStripping 2).
4. Changing prototype-feeding components needs Revert -> change -> Convert, or the old prototype keys stay; the
   editor then logs "Removing prototype N but X instances still reference it" (harmless in edit mode).
5. execute_code + BuildPipeline.BuildPlayer works, but Unity stalls when its window is unfocused or "stuck"
   (build 59's first attempt hung 20 min): ask Carlos to focus/restart Unity.
6. The [PERF] draws/tris counters undercount BRG. Trust fps, 1% low, CPU/GPU ms.
7. The weather system copies the fog Volume's profile at runtime; anything toggling Volume components must edit
   the runtime copy (SceneEffectsToggle does since C-040).
8. Carlos's editor shortcut profile had F6 on Terrain/Detail Brush (removed) and still has F7 on
   Terrain/Stamp Terrain (harmless so far).
9. Scene 09 has enemies/NavMesh off like 07; numbers are a controlled run, not a fight.
