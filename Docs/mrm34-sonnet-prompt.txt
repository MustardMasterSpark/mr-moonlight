WHAT JUST HAPPENED (fully resolved, no follow-up needed)

Carlos reported Spotters occasionally visible lying flat on the ground for a couple seconds after
spawn, standing up once he approached or they started/stopped moving. Root cause:
`AC_Spotter.controller`'s `Downed` Trigger parameter had `defaultBool = true` (every other trigger
was `false`), so every fresh instance auto-fired into the Downed animator state via its
`AnyState -> Downed` transition before any script ever ran — confirmed in total isolation (bare
GameObject + Animator + controller, zero scripts, still auto-transitioned). Fixed by resetting the
default to `false` and saving the asset. Verified the controller change directly; a live in-Editor
re-test still needs a fresh Play session on Carlos's end (was mid-verification when this session
ended).

Full writeup: `Docs/spotter-downed-trigger-lessons-learned.md`. Also worth reading before touching
any OTHER character's Animator Controller (Blaze, Wendigo, Tracey, anyone future) — Carlos
specifically asked this lesson be kept in mind for those: **if an Animator Controller misbehaves
identically across every instance with no script anywhere referencing the state/trigger by name,
check parameter default values in the Parameters tab before suspecting code.** A Trigger left
checked in that tab before saving serializes as a stuck `true` default — invisible in the graph
view.

Also worth reusing: the debugging *method*, not just the fix — see memory
`feedback_editor_watcher_for_timing_bugs`. For any bug that reproduces reliably but briefly in Play
Mode (a few seconds), don't try to time a manual pause-and-inspect through chat — entering Play Mode
reloads the domain and wipes anything installed from Edit Mode first, and the round-trip alone eats
a short window anyway. Instead write a throwaway `[InitializeOnLoad]` Editor script that self-arms
on `EditorApplication.playModeStateChanged` and freezes/logs automatically. Delete it once done.
