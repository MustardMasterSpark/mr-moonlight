TRAPS FOUND, DON'T REDISCOVER THESE
------------------------------------
- Gore Simulator's own automatic bone-detection (AutoSetupHumanoid) is built for Mixamo-style bone
  names and silently fails on this rig: CC_Base_* (AccuRig/Character Creator) delegates limb mesh
  weight to *Twist01/02 helper bones, not the named joint bones themselves (CC_Base_L_Upperarm etc.
  carry ZERO vertex weight). Had to build the 16-bone list by hand instead, one bone per
  EnemyHitbox zone, using PampelGames.GoreSimulator.Editor.MeshEditorUtility.AddBoneToClass via
  reflection (internal method) rather than the vendor's own auto-setup.
- CC_Base_Head is NOT covered by that manual 16-bone list's targetNames array — it was only present
  on the first (duplicate) prefab because of a leftover from an earlier failed AutoSetupHumanoid
  attempt. Redoing the setup from scratch on the original prefab produced 15 bones, not 16, silently
  missing the head, until caught. If this is ever rebuilt a third time: CC_Base_Head needs adding
  explicitly, it won't come along for free.
- Gore Simulator's real one-time setup ("Initialize" button in its custom inspector) has no clean
  public static API — it's a private method (GoreSimulatorInspector.InitializeComponent) on a
  UI-Toolkit custom Editor. The working technique: UnityEditor.Editor.CreateEditor(gs, editorType)
  (its real OnEnable() auto-loads default SO references), then reflection to invoke
  InitializeComponent() on that editor instance. This is idempotent — safe to re-run after changing
  a setting like meshesPerBone, it won't duplicate colliders/joints (both creation utilities check
  for an existing component first).
- SubModulePhysics is NOT auto-added to cutModules by Gore Simulator's own setup — without it,
  severed pieces have no Rigidbody/Collider and just float in place, ignoring gravity entirely. Had
  to add it manually (collider: Automatic, rigidbody: true) after the bake.
- Compiling scripts (refresh_unity with compile:"request") while Carlos is mid-Play-Mode forces a
  domain reload that interrupts his test and can throw one-off "missing script"/NullReferenceException
  console noise. Check play_mode.is_playing via the editor/state resource before forcing a compile;
  if he's playing, wait or warn him first.
- UnityMCP manage_prefabs save_prefab_stage/close_prefab_stage occasionally report a transient
  "Unity plugin session disconnected" error even though the operation actually succeeded — always
  re-check the prefab stage state (PrefabStageUtility.GetCurrentPrefabStage()) before retrying, don't
  assume failure.
