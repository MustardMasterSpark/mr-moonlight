## Addendum 2026-08-31, late night — first Gaia vegetation spawn attempt: STOP, do not trust current scene state

Carlos finished painting all 9 biome layers + Path by hand and asked me to take full control of
setting up Gaia spawners for a first baseline pass, using §7's Stratum-A (canopy/primary) species

### What's actually built (the part that's good)

Under a new `Vegetation Spawners` GameObject: one `Gaia.Spawner` per biome (Forest, AutumnForest,
EerieForest, HereticForest, Beach, Mountain, FlakTower, Fountain, Glade — **not** Path, confirmed
empty), each with:
- One inactive `TerrainTexture`-type `SpawnRule` that exists purely as a mask source, pointing at
  that biome's `TerrainLayer`.
- One `GameObject`-type `SpawnRule` per Stratum-A species (real prefab from
  `Assets/_Project/Art/VegetationPrefabs/` or the `RetroRealism`/`TerrainSampleAssets`/
  `GrassFlowers` prefab folders), with `m_locationIncrementMin/Max` set to the doc's exact spacing
  values, masked to the biome's `TerrainTexture` ImageMask so it only spawns where that biome's
  layer is actually painted.

**This wiring is correct and works** — verified end to end on the Fountain spawner (438 instances,
all inside the painted Fountain patch). Getting here took real debugging, worth knowing for next
time:
1. `spawner.Spawn(false)` (the "normal" public API) routes through `GaiaSessionManager.Spawn` →
   `GetOrCreateSessionSpawners`, which produced **zero instances with zero errors** — silently
   broken for a spawner that isn't part of a recorded Gaia session in the expected way. **Use
   `spawner.AreaSpawn(new List<Spawner>{spawner}, spawnArea)` directly and manually drain the
   returned `IEnumerator` with a `while(coro.MoveNext())` loop instead** — that's the reliable path
   from script.
2. Spawned GameObjects land under `<Terrain>/Gaia Game Object Spawns/<SpawnRuleName>/`, **not**
   under the Spawner GameObject. Check child counts there, not on the spawner.
2. The real bug that cost the most time: **`Gaia.ImageMask`'s `TerrainTexture` operation resolves
   its target layer by comparing `ResourceProtoTexture.m_texture` (a `Texture2D`) against each
   terrain layer's `diffuseTexture`** (`TerrainHelper.GetLayerFromPrototype`, matches by
   `PWCommon5.Utils.IsSameTexture`) — it does **not** use `ResourceProtoTexture.CurrentLayer`
   (the `TerrainLayer` reference/GUID) despite that property existing and looking like the obvious
   thing to set. Setting only `CurrentLayer` produces a mask that silently resolves to
   `Texture2D.blackTexture` (zero everywhere) with no error logged anywhere. **You must also set
   `resourceProtoTexture.m_texture = terrainLayer.diffuseTexture`** for the mask to actually find
   the layer. Worth a Linear note if this bites anyone doing biome-masked spawning again.

### What's broken: instance counts are catastrophically over the doc's design intent

First full batch run across the remaining 8 biomes produced **862,743 GameObjects** in
`Gaia Game Object Spawns`. That is not a usable baseline — it's a scene-destroying number. Two
compounding causes, both understood now:

1. **§7's spacing values assume the doc's placeholder hectare areas, not the real painted areas.**
   The doc says this explicitly (§6.2) but the implication didn't register until the numbers came
   back. Density (instances/ha) from spacing is correct and area-independent; the *absolute count*
   scales with actual painted area, which turned out far larger than the placeholders for some
   biomes — real measured coverage (2026-08-31 alphamap read): Forest 36.4% of the terrain (~38 ha
   vs 16 ha assumed), Beach **46.5%** (~49 ha vs 5 ha assumed), AutumnForest 5.4%, Mountain 4.9%,
   FlakTower 3.6%, Glade 0.9%, EerieForest 0.9%, HereticForest 0.8%, Fountain 0.4%. Forest at 2.4x
   the assumed area is a reasonable, expected scale-up. Beach at **9.7x** is not — the Beach layer
   was painted "everywhere at or below sea level + 5 m" (§6.1), which includes a huge amount of
   underwater seafloor, not just a shore band.
2. **Nothing stopped Beach's rock species from spawning underwater.** `RF_Boulder1` alone (spacing
   1.0-1.6 m) placed **487,111** instances — the overwhelming majority almost certainly on the
   seafloor under Beach's painted area, not on an actual visible shore. This is the dominant
   contributor to the 862k total. Several other biomes are individually fine (Fountain 438,
   HereticForest ~1,100, EerieForest ~1,000) — the blowup is concentrated in Beach and in a few
   very-tight-spacing ground-cover species (`TSA_GrassDry_C` 36,794, `AP_M6_Rock_FieldStoneStone05_SM`
   80,517, `AP_M6_Rock_FieldStoneStone06_SM` 63,672, `AP_TurtleLake_Rock_LakeRock02_SM` 63,681 —
   these read like Mountain/Beach rows whose spacing was tuned for a small assumed area, applied to
   a much bigger real one).

**Fix for next attempt, before spawning again:**
- Add a height mask (`HeightMaskType.RelativeToSeaLevel`, min at sea level) to the Beach spawner
  specifically, so shore-rock/driftwood rules can't place below Y=8. This was skipped this round on
  the assumption the painted mask alone would be sufficient — it isn't, because Beach's paint
  extends underwater by design.
- Either accept the larger-than-doc absolute counts as correct (density/ha is right, it's just more
  hectares than planned) or add a `rule.m_maxInstances` cap per species as a safety net regardless
  of area.
- Re-run **one biome at a time** with a child-count check after each, not all 8 in one batch —
  this would have caught the Beach blowup immediately instead of after a ~10-minute blocking spawn
  that also froze Carlos's Play Mode entry/exit for several minutes each way (see below).

**The standard vegetation pipeline going forward — full detail in the `mrm70-vegetation-flora-pipeline`
memory, summary here:**

1. Clean up existing spawned vegetation first.
2. Split every species by §7's **Blocks** column when building Gaia rules: nonzero Blocks (needs
   real physical collision) → `SpawnerResourceType.GameObject`. `—` Blocks (pure decoration —
   ferns, grass, small flowers) → `SpawnerResourceType.TerrainDetail`, **not** GameObject. Flora
   (`com.ma.flora`, see `Flora Scene Settings` in the scene) already auto-accelerates terrain
   details/trees natively (`EnableTerrainFoliage` + `AutoRegisterTerrains`) — zero real GameObjects
   ever exist for this category, so instance count there is nearly free regardless of how high it
   goes.
3. Run the Gaia spawn **one biome at a time**, checking the instance count after each before moving
   to the next (batching all 8 blind is what caused the 862k blowup).
4. For the GameObject-type (collidable) instances only, run a one-time post-pass adding
   `MA.Flora.FloraInstanceRenderer` to each. Verified against Flora's own source: registration is
   one-time (`OnEnable`, no per-frame code), and it sets `forceRenderingOff` on the object's own
   `MeshRenderer` so Flora's batched GPU rendering fully replaces Unity's default draw — not a
   double cost. Collider/Transform/physics are untouched, so real collision is kept. This does
   **not** remove the baseline cost of having a real GameObject+Collider (physics/memory scale with
   that count regardless) — it only makes the *drawing* of that count cheap. The real fix for "too
   many instances" is step 2, keeping the decorative bulk out of the GameObject path entirely, not
   leaning on Flora to make GameObjects cheap.
