WHAT EXISTS AND WORKS — DO NOT REBUILD ANY OF THIS
=============================================================================

The whole demo loop is four authored lines:

    wait       seconds=1
    objective  kill_spotters  text="Homework: Kill 20 old timers"  kills=20  kind=Spotter  for=8
    wait       objective=kill_spotters
    win        "Good boy"

THE ONE RULE OF THE FORMAT: every line fires and the director moves straight to the next one. The
only line that ever blocks is `wait`. Do not add hidden blocking behaviour to any other verb — that
rule is the entire reason the format is readable, and it is the deliberate correction to the
deprecated SLDD that Carlos abandoned for being unreadable.

F6/F7 RESTORE THEMSELVES ON PLAY-MODE EXIT AND MUST KEEP DOING SO. `SceneEffectsToggle` writes to
the shared Volume PROFILE ASSET by design, and an asset edited during play mode is NOT rolled back
the way a scene object is — so without the restore, one cheat-key press would quietly change the
project's shipping look. `SceneEffectsDebugToggle` snapshots the state in Awake and puts it back in
OnDisable, only if a key was actually pressed. F8 needs no equivalent because `TimeManager` drives
scene objects, which play mode rolls back on its own.

Note: HAZE fog is currently OFF in the shared profile (pre-existing, not from this work).
`SceneEffectsToggle` has a "Restore Ship Defaults (Fog + CRT On)" context menu.

=============================================================================
KNOWN GAPS AND TRAPS — read these, they will save you a session
=============================================================================

  - URP LOGS ONE ERROR EVERY PLAY SESSION, and it is expected: "Too many additional punctual lights
    shadows to look good, URP removed 50 shadow maps." Cause is the 51 Spotter hand lamps, each a
    shadow-casting point light. URP handles it and the scene runs at 152-156 FPS, but a standing red
    line will eventually hide a real one. The one-field fix is `Lamp Light` -> Shadow Type ->
    No Shadows on `Enemy_Spotter.prefab` (or Soft -> Hard to halve the atlas cost). LEFT ALONE ON
    PURPOSE: which lamps cast shadows is an art decision and 50 of the 51 already effectively don't.
    Ask Carlos before changing it.

  - A FLARE ON TOP OF 51 SPOTTERS IS UNTESTED. `SpotterFlareCall` summons a wave when a Spotter is
    isolated; `SpotterPanicCall` summons another when one is hurt. The reinforcement maths has never
    run at this population. Watch the live enemy count during a real playthrough before assuming it
    is fine. This is MRM-34 tuning territory, not a director bug.

  - THE PLAYER TAG IS ON THE `Body` CHILD, NOT THE PLAYER ROOT. Both are tagged, and
    `FindGameObjectWithTag` returns `Body`. That is CORRECT for Blaze (physics reads the collider's
    own tag), so it is the right chase target — but `GetComponentInChildren` from it finds nothing,
    because `BurntwaxPlayerBridge` lives on `Player/MrMoonlight Systems`, a sibling branch. Search
    from `transform.root`.

  - NEVER NULL A STATIC EVENT FROM Awake/OnEnable. Scene wake order is undefined, so it silently
    deletes subscribers that woke first. `EventSignals` was fixed for exactly this. Use
    `[RuntimeInitializeOnLoadMethod(SubsystemRegistration)]`, which runs before any scene object.

  - THE MCP SCREENSHOT TOOL SOMETIMES FALLS BACK TO DIRECT CAMERA RENDER, which excludes every
    Screen Space - Overlay canvas — so the HUD, the FPS counter and the whole end panel vanish from
    the capture even though they render fine. It did this consistently while `Time.timeScale == 0`.
    Do NOT read a missing HUD in a screenshot as a bug. Confirm component state first, and if you
    need a real capture set `timeScale = 1` in a SEPARATE tool call before shooting (a same-call
    change does not get a rendered frame in time).

  - `execute_code` runs as a METHOD BODY. No `using` directives — fully qualify everything. And
    write `UnityEngine.Object.FindObjectsByType`, never bare `Object`, or you get an ambiguous
    reference against `object` and a cascade of bogus StringBuilder errors.

  - SIGNALS LATCH. Once raised, a signal stays raised for the level, and a `wait` on an
    already-raised signal returns immediately. This is deliberate deadlock protection. The cost is
    that a signal cannot be waited on twice — raise a second, differently-named one.

  - DEADLOCK POLICY IS PER-CONDITION AND DELIBERATE. World waits (zone/signal/sequence) time out
    after `EventWaitDefaultTimeout` (180s). Progress waits (objective/kills/group) wait FOREVER on
    purpose — timing them out would hand the player a win they did not earn. Do not "fix" the latter
    by adding a timeout.

HOW THE 51 SPOTTERS WERE PLACED — reproduce this if you re-scatter them
=============================================================================

Under the `Enemies` holder: 50 placed by script plus the one that was already hand-placed (moved in).
All are real prefab instances of `Assets/_Project/Prefabs/Enemies/Enemy_Spotter.prefab`.

Rules enforced at generation:
  - REACHABILITY-GATED. Every point had to return `PathComplete` from `NavMesh.CalculatePath`
    starting at the player spawn. This single test does two jobs: it keeps them all on the main
    island (the small island and the other disconnected NavMesh components are excluded
    automatically, with no hardcoded geometry), AND it guarantees the kill objective is completable.
    KEEP THIS RULE if you re-scatter. 72 candidates were rejected on it alone.
  - 90m clear zone around the player spawn (attack-state sight range is 40m). Closest is 106m,
    farthest 481m.
  - 30m minimum spacing between Spotters.
  - `Random.InitState(11)` so the layout is reproducible.

`EnemyPatrolRoute` is in wander-radius mode with no waypoints, so each wanders around its own spawn
point — no extra wiring needed per Spotter.

Measured 152-156 FPS with all 51 alive, both at spawn and in the densest cluster. Not a perf problem.
Note that each Spotter carries a shadow-casting point light (the hand lamp), 52 in the scene; URP
culls by distance, but "Reduced additional punctual light shadows resolution..." warnings are now
more frequent. That is URP fitting its shadow atlas, not an error.
