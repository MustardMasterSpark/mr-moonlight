4. TRAPS ALREADY FOUND (don't rediscover these)
===========================================================================
- A hull that comes back as exactly 1 segment is NOT proof the limb has no real seams - it can
  mean the mesh has many fine, evenly-spaced real ring cuts (a single continuous tapering tube,
  e.g. `AP_AlaskaCedar_001_2`) whose per-gap size is individually small relative to the whole span,
  which an earlier version of the "smallest real gap must be a % of total span" guard wrongly
  rejected even though the ratio-based signal was a clean 6x. Fixed 2026-09-17 by dropping that
  floor (kept only a small absolute floor) and raising the confidence ratio 2x -> 2.5x. If a
  "should be easy" single-limb tree comes back as 1 piece again, use `DumpRingProjection` before
  trusting it - don't assume "no real seams" without checking.
- Colliders attach to the "Visual" child (the object with MeshFilter), never the root, for this
  asset library. Clicking the root and seeing no Collider component doesn't mean none exists.
- Two delete buttons look similar, do very different things: "Delete generated colliders and game
  objects" (top Tools row) is safe/repeatable. "🗙 All" in the Hulls list deletes the hull
  *definitions* (your painted work) - don't use it mid-process.
- Convex Hull is the CORRECT type for a pre-split limb, not a fallback - Auto/VHACD on an
  already-simple selection just adds noise. This is why Auto "never gives a good result" once you
  start manually splitting - it's the wrong tool for that stage, not a preset problem.
- `SplitPaintedHullsAtRingSeams` takes an optional `onlyHullNames` filter - use it when adding a
  missed limb after the fact, or it reprocesses already-split hulls and over-fragments them.
- Domain reloads (script recompiles) do NOT kick Prefab Mode / the Rigid Collider Creator window
  closed in this Unity version - confirmed safe to edit the script and recompile mid-session.
  Exiting Prefab Mode (Carlos navigating away / saving) does lose the live in-memory session
  though - re-check `PrefabStageUtility.GetCurrentPrefabStage()` before assuming state persists.
- Scene View screenshots render washed-out/gizmo-less when the Editor window isn't OS-focused -
  known quirk, not a bug, don't chase it - just note the limitation and ask Carlos to look himself.
- Before concluding a "missing collider" is a bug: compare total selected-triangle count across
  all hulls before vs after the operation in question. It never drops triangles - if the count
  matches, the gap was never painted in the first place.
- After any re-run following a bug fix (or any time colliders get regenerated more than once on
  the same hull set), explicitly verify the OLD collider(s) are actually gone, not just that new
  ones exist alongside them. Carlos asked this directly after the AlaskaCedar fix ("did you delete
  the overall big convex hull before generating the new ones?") - the right answer came from
  checking live component state (collider count == hull count, largest single collider's mesh tri
  count sane relative to the others), not from remembering the steps taken. Don't answer this kind
  of question from memory of what you did - re-check the live state every time it's asked.
