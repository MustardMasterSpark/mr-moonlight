## What's actually finished

- **8 painted biome terrain layers**, splatmap-driven, matching `Docs/mrm70-biome-vegetation-strategy.md`.
- **34,816 tree/prop instances + 27 grass/detail prototypes**, placed by Vegetation Spawner
  (`Tools/Mr. Moonlight/Vegetation/...`, run order Prep → Composer → Painter → Setup → Cull).
- **Flora Renderer** replaces Unity's native tree/detail draw path: 535 draw calls, ~505 FPS
  baseline (measured 447–490 FPS again after the PSX migration, build 21). Tree collision verified
  intact both before (docs) and after (this session's raycast sweep) the material migration.
- **HAZE volumetric fog + Retro Shaders Pro CRT** wired on `PC_Renderer`, values tuned by Carlos.
- **PSX material migration done**: all 28 vegetation materials + `M_IslandTerrain.mat` moved
  `URP/Lit` → `RetroLit`/`RetroTerrainLit`. Approved profile (baked into
  `PSXMaterialMigration.cs` as the tool's defaults, so new materials land here automatically):
  Point Filtering, View-space Vertex Snapping, **Affine Texture Strength = 1** (Carlos live-tuned
  this up from the initial 0 on 2026-08-25), Resolution Limit / Colour Depth Limit effectively off.
  Terrain has no Affine property to set.
- **`Scene Effects Toggle` dev tool** (`Assets/_Project/Prefabs/DevTools/Scene Effects Toggle.prefab`,
  already placed in `Island.unity`): checkboxes to kill HAZE fog (both the global Volume override
  *and* the separate `HazeDensityVolume` on "HAZE Explorable Area Fog" — two independent fog
  sources, easy to miss one) and the CRT effect while staging, without asking for it each time.

## What's still open (the actual gaps)

1. **Mine, cavern, and the remaining locations are not built.** This is the concrete blocker that
   triggered the pause — waiting on Carlos's own Blender prep for those props/textures.
2. **New tree models (job 2 of the original Flora-phase plan) never landed.** When they do: clear +
   respawn in one motion using `Docs/Design/Island-Terrain-Reference/Map/biomes.png`, same five
   editor tools, same run order. Do not clear early — the island has to stay demoable.
3. **Wind (job 3) was never started.** Flora enables animated/motion-vector shaders but doesn't
   author wind itself — it's a Shader Graph someone has to write (vertex displacement by time +
   world position, masked so trunks stay planted). Grass currently only gets wind from Unity's
   built-in detail shader.
4. **14 of 27 detail prototypes still don't render under Flora** (`GrassType.Texture` billboards on
   Unity's built-in grass shader, not BRG-compatible). Fix was scoped to job 2 (rebuild as
   single-mesh crossed quads on RetroLit) but never done.
5. **`RetroTerrainLit`'s multi-pass shader has a real compile error**, found verifying build 21:
   `Hidden/Retro Shaders Pro/Terrain/Lit (Base Pass)` throws `invalid subscript 'uvSplat01'` on the
   d3d11 variant specifically (this project runs d3d12, where it's fine — visually confirmed, a
   layer-6/second-pass sample rendered correctly). A duplicate-keyword message in the Add Pass is
   almost certainly harmless. Flagging because "Direct3D12, Direct3D11 (auto)" per
   `Docs/pc-build-target.md` means some player machines could hit the broken variant. This is a
   Retro Shaders Pro asset bug, not something our material settings can fix.
6. **Barrier rock walls were never placed** (the magenta polylines on `biomes.png` — still the
   least legible thing on that map per open question #4 in the strategy doc).
7. **Open questions from `Docs/mrm70-biome-vegetation-strategy.md` §7 are still open**: birch vs.
   pine for autumn trees, the tree LOD cull distance (currently a guess, `LodCullScreenHeight =
   0.015`), whether enemy vision needs trees on a dedicated layer.
8. **Density/LOD were tuned once, by eye, and never re-measured** against a stable build after the
   PSX shader swap or the fog/CRT tuning.

## Why pausing here is the right call

Carlos is asset-bottlenecked on the remaining locations and doesn't have new tree models ready
either — there's no more vegetation/terrain work to do productively until that lands. Meanwhile the
Sept 1 playable-loop gate needs mechanics and animation more urgently than terrain polish. Building
those in parallel, in `Sandbox.unity` (already registered in Build Settings, build index 1 — the
scene with `DefenseTest`/`HealthTest`/`MeleeTest`/`PitchTest`/`Controller UI Test` prefabs from
earlier stat-testing work), keeps iteration fast: no 34,816-instance terrain to render while
tuning a melee hitbox.

**Deliberately deferred, not forgotten:** full enemy AI/pathfinding behavior. Nav-relevant work
needs real level geometry to test against — building it against a flat placeholder plane risks
tuning against constraints that don't match the real island and redoing it once terrain exists.
Basic state/detection logic can still be built now; the pathfinding-through-terrain part waits.

**Carry the hard rules over into the new work:** unlike vegetation/staging numbers (explicitly
exempted, see `feedback_tunables_during_prototyping` memory), core gameplay mechanics — health,
melee damage, defense values, movement — are exactly what `MoonlightTunables` is for. No exception
here.
