TRAPS THAT ALREADY COST TIME TODAY (all in MRM-76's comments in more detail)

  - Editing ANY script while Unity is in Play Mode forces a domain reload that nulls out runtime
    wiring (GunStateMachine and similar threw NullReferenceException floods, twice). Always
    manage_editor stop before editing code, even mid-session; re-enter play mode after.
  - Play mode only ticks while the Unity Editor window has OS focus — same trap as MRM-34, still
    true. If Time.time / a coroutine looks frozen, that's why.
  - A prefab asset and its live scene instance are separate — a scene-instance-only edit doesn't
    reach future-spawned copies (e.g. reinforcements). This session's pattern: edit via
    PrefabUtility.LoadPrefabContents/SaveAsPrefabAsset for the source, AND the live scene instance
    if one already exists, in the same pass.
  - Vendor code that needs its own asmdef to be referenceable from MrMoonlight.Runtime: Blaze,
    Ian's Fire Pack (Assets/ThirdParty/, needed IansFirePack.asmdef). Vendor code that does NOT
    (Plugins/ folder, auto-visible): DOTween. Check which situation a new vendor script is in
    before assuming either way.
  - AssetDatabase.ExportPackage with IncludeDependencies|Recurse is the clean way to pull one
    prefab and only its actual dependencies out of the Playground project, rather than copying
    a whole asset-pack folder by hand and guessing what's shared.
