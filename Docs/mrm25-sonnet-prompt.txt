TRAPS THIS SESSION PAID FOR — do not rediscover these
  1. A MALFORMED GUID SILENTLY KILLS THE WHOLE .inputactions ASSET.
     A binding id with a 2-digit second group made Unity's importer reject the entire file. The
     asset still existed, the generated C# wrapper still compiled against the OLD file, and every
     InputActionReference resolved .action to null. Symptom looked like "my new actions don't
     exist". The patch script now validates every id with uuid.UUID(). If input goes strange,
     check the console for "Could not parse input actions in JSON format".

  2. CHANGING A C# FIELD INITIALIZER DOES NOT CHANGE AN EXISTING PREFAB.
     MoonlightStartingLoadout kept its serialized four-weapon list from MRM-9 however the
     initializer read. Cost a play-mode run. Anything that must actually change on an existing
     prefab has to go through SerializedObject — see MoonlightWeaponSetBuild.ConfigureLoadout.

  3. MATCHING AN INPUT ACTION BY NAME IS NOT ENOUGH.
     The vendor asset also has an action called "Lean", so a pasted FPSBodyLeanInput looked correct
     by name while still pointing at the vendor asset. Compare by object identity.

  4. "Inventory Is Full" CAN MEAN A TAG RESTRICTION, NOT CAPACITY.
     The Syringe was refused by the Holster's TagContainerRestriction with 3 slots free, because its
     item definition shipped untagged. Check restrictions before capacity.

  5. READ THE FRAME BEFORE BELIEVING IT.
     An attachment check in the same frame as SelectAtIndex reported every scope inactive — the
     equip had not finished. Same lesson as mrm9-hqfps-integration.md §9b.

  6. RETYPING A SERIALIZED FIELD IS A DATA MIGRATION.
     MRM-9's AudioSequence -> AudioData retype left five newly-imported firearms completely silent.

  7. AudioRandomContainer CANNOT BE CREATED NORMALLY. Constructors are internal; CreateInstance and
     ObjectFactory both fail; Activator produces a broken asset. Only
     DoCreateAudioRandomContainer.CreateAudioRandomContainerFromSelectedClips works, by reflection.
     MoonlightWeaponAudioBuild already does this — reuse it, do not re-solve it.
