WHAT THIS SESSION BUILT — DONE, COMPILED CLEAN, **NOT YET LIVE-TESTED**
===========================================================================

Per feedback_confirm_before_declaring_fixed (memory): only a clean compile was verified this
session (via UnityMCP read_console — zero errors from the changed files). Nobody has actually
pressed Play and watched a Spotter relocate or turn aggressive. **Do not tell Carlos this is
done until it's been run** — verify in Play Mode (or a build, per verification_requires_a_build
memory if it's anything perf/timing-sensitive) before reporting it working.

**1. Relocation.** A second coroutine, `RelocationLoop`, runs every
`MoonlightTunables.SpotterRelocationCheckInterval` (20s default — deliberately much slower than
the 5s population top-up loop). It:
   - Counts alive Spotters within `SpotterRelocationNearbyRadius` (150m, bigger than the 100m
     spawn ring on purpose — hysteresis, so a Spotter freshly spawned at the ring's edge isn't
     immediately re-flagged as a straggler).
   - If that nearby count is short of the current population floor, warps the farthest
     stragglers (via `NavMeshAgent.Warp`, not a raw transform set — keeps Blaze's internal nav
     state consistent) into a fresh spawn-ring point around the player, reusing existing
     Spotters instead of instantiating more (the global floor is already met, so TopUp wouldn't
     spawn anything anyway).
   - Skips any straggler whose `BlazeAI.state == BlazeAI.State.attack` — never yanks a Spotter
     out of a fight the player can see.

**2. Aggression escalation.** New `_totalKills` counter on the manager itself, incremented via
its own `EnemyHealth.AnyDied` subscription (not routed through ObjectiveTracker — deliberately
self-contained, per this file's own doc comment).
   - Tier 1 at `SpotterAggressionKillThreshold1` (15): population floor +5
     (`SpotterAggressionPopulationBonusTier1`), top-up interval tightens 5s→3s
     (`SpotterAggressionCheckIntervalTier1`), and every Spotter placed from then on (fresh spawn
     *or* relocated straggler) gets `BlazeAI.SetEnemy(player, true, true)` one frame after
     placement — straight into attack state chasing the player, same call
     EnemyReinforcementSpawner.EngageNextFrame uses for a flare wave.
   - Tier 2 at `SpotterAggressionKillThreshold2` (30): floor bonus replaces (does not stack
     with) tier 1's, going to +10 (`SpotterAggressionPopulationBonusTier2`); interval tightens
     further to 1.5s (`SpotterAggressionCheckIntervalTier2`).
   - Escalation only affects Spotters placed *after* a threshold is crossed — an already-alive,
     already-idle-nearby Spotter does not retroactively flip to attack. This was a deliberate
     scope call (matches "spawning more + sending them" reading as one action for newly involved
     Spotters), not confirmed with Carlos either way — flag if he expected the existing ones to
     go aggressive too.

**3. New tunables**, both in MoonlightTunables.cs under the existing "Demo Spotter population
manager" header (relocation fields) and a new "Demo Spotter aggression escalation" header
(aggression fields) — see the file for exact defaults, all listed above.
