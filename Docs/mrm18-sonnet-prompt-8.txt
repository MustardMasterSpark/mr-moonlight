===============================================================================
OTHER TRAPS STILL LIVE (unchanged unless noted)
===============================================================================
- Play Mode discards scripted component/scene edits on stop — confirm Edit Mode before an edit you
  need to persist, re-verify after Carlos stops Play.
- `manage_scene` edits don't flush to disk by themselves — explicit `manage_scene action=save`
  after any batch of changes you need to survive a scene switch or Editor restart.
- Raw file edits (Edit tool) to an already-open scene/asset do NOT hot-reload into the live Editor
  session — the in-memory object stays stale until something forces a reimport, and even then a
  domain reload can silently re-read the OLD on-disk value if you saved through the API in between.
  Prefer live `SerializedObject`/`execute_code` edits over raw YAML edits when the target is already
  open, and always read a value back after any save to confirm before trusting it.
- The Unity Editor can go fully unresponsive to the MCP bridge while unfocused mid-operation
  (confirmed again this session, cost several minutes) — if `editor/state` starts returning "ping
  not answered" and doesn't recover after a couple of retries, ask Carlos to click into the Unity
  window rather than continuing to hammer retries.
- DOTween shortcut extensions (`.DOFade`, etc.) are unreliable in this project — `AudioSource` and
  now `CanvasGroup` both fail to resolve despite the core engine working fine. Default to
  `DOTween.To(() => obj.prop, v => obj.prop = v, target, duration)` for any new tween rather than
  trying the shortcut first.
- `manage_camera` screenshot with an auto-picked camera excludes Screen Space - Overlay canvases
  entirely — either omit `camera` (uses ScreenCapture API, includes overlay UI) or use
  `capture_source: "scene_view"`.
