===============================================================================
BIGGEST TRAP THIS SESSION WILL HIT - CHECK BEFORE TRUSTING ANY TMP FONT
===============================================================================
Hit THREE separate times last session: a freshly-created TextMeshPro font asset in Dynamic
population mode can have a completely dead atlas - `m_CharacterTable`/`m_GlyphTable` empty on disk,
runtime glyph generation silently failing. Two different symptoms, same root cause:
- Total lookup failure -> every character renders as a solid "missing glyph" box.
- Metrics resolve fine, but the atlas texture pixels at the glyph's rect are 100% alpha 0 -> text
  is fully invisible, occupying its layout space normally (looks like nothing is there at all).

**Before doing ANY work with a font not already proven this session** (i.e. anything other than
`GutenbergTextura SDF`, `GabrieleBandAah SDF`, `NotoSerif SDF` - those three are now confirmed
working), check it first:
```csharp
UnityEngine.Texture2D tex = (UnityEngine.Texture2D)someTMPFontAsset.atlasTexture;
// sample a real glyph's rect, check for non-zero alpha - don't trust metrics alone
```
If it's dead: reimport the source `.ttf` (`manage_asset` action=`import`), then
`fontAsset.ClearFontAssetData(true)` + `AssetDatabase.SaveAssets()`, then force a mesh rebuild on
anything using it and re-check pixel alpha. This is very likely to bite again on whatever font gets
used for the main menu title/buttons if it's a freshly-created asset nobody has actually rendered
text with yet.

  is cosmetic, Editor-only, confirmed via source it cannot touch Play Mode or a build - don't
  re-investigate it as a real bug, Carlos already chose to live with it.
- Baking a manually-resized/repositioned object's transform to clean values (scale->1, folded into
  sizeDelta/fontSize; position->0, compensated in children): capture each child's WORLD
  `transform.position` first, do the cleanup, then set `transform.position` back to the captured
  value - let Unity solve the local offset, don't hand-compute it.
- `TMP_Text.preferredWidth`/`preferredHeight` read right after a `sizeDelta` change can be stale/
  wrong (rect-dependent feedback loop) - use `GetPreferredValues(text, wideWidth, 0)` with an
  explicit wide width instead for reliable single-line measurement.
