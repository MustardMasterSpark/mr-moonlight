## Facts already known about vegetation colliders on this project (don't re-derive)

- The Island's vegetation is **~5,900 individual GameObject colliders** (memory: [[mrm27_island_navmesh_facts]],
  [[mrm70_vegetation_spawner_facts]]) — collidable species are GameObject + FloraInstanceRenderer,
  not TerrainDetail (that's reserved for decorative grass with no collision).
- **Unity terrain trees reject MeshColliders outright** (memory: [[webgl_gles3_gotchas]]) — this is
  still true post-platform-switch, not a WebGL-only limitation. If Technie's output is a
  MeshCollider and any vegetation is still placed as a terrain tree (rather than a GameObject), it
  will silently fail to collide. Check which placement method each species actually uses before
  assuming a collider swap will work.
- **A terrain tree prefab's root transform is ignored by Unity's terrain system** (memory:
  [[mrm70_terrain_tree_transform_bug]]) — irrelevant if everything here is GameObject-placed, but
  verify that assumption rather than inherit it blind.
- Vegetation placement tooling lives at `Tools/MrMoonlight/Vegetation` in the Unity menu (memory:
  [[mrm70_vegetation_flora_pipeline]]).
- Carlos's stated goal for adopting this was **performance** (fewer/cheaper colliders than
  whatever's there now), not correctness — so the evaluation should measure something (collider
  count, draw calls, or profiler numbers), not just "does it visually look right."
